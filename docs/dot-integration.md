# dot 接入与持续维护

更新时间：2026-10-13。主职责：首个日常入口怎样读取个人库、接收脱敏材料并回写理解。

首版把 dot 作为配置引导、日常交流和理解维护入口。dot 沿 Harness 的步骤协助用户完成来源选择与操作；本地工具组织资料、工作区和读取约定，再依据用户选择把个人 Wiki 与脱敏来源提供给 dot。

## 自然语言 Bootstrap

已关联本项目的 dot 收到“初始化”“执行初始化”“安装”等个人 Agent 启动请求，直接按 [BOOTSTRAP.md](../BOOTSTRAP.md) 调用非交互入口，再在聊天中引导。dot 命令生成的交接说明包含真实工作区和可执行的 Bootstrap 命令，个人上下文入口的 AGENTS.md 也指向自己的 BOOTSTRAP.md；云端包携带完整流程、命令文档和工具，使用包内相对路径启动。

新 dot 首次需要提供项目位置并完成电脑连接，随后按交接说明将入口记到其已有持续笔记；已经接入后使用短指令即可。自然语言触发由已加载的项目规则执行。Codex 在项目会话启动时读取 AGENTS.md；已有会话可重新读取当前入口规则。[官方项目指令说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md#how-codex-discovers-guidance)

## 已核对的平台能力

dot 有云端电脑，也可以连接用户电脑并创建或继续本地工作任务。使用本地电脑时，电脑需要在线且 ChatGPT App 保持打开；电脑权限、消息入口与插件连接分别配置。[官方电脑与应用说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)

dot 使用当前对话、相关记忆和自己的持续笔记；新任务接收该任务的上下文，连接电脑不自动带来全部历史聊天。固定时间的重复工作需要保存 schedule，并设置工作、时间及时区、通知条件和结果位置。[官方任务与记忆说明](https://learn.chatgpt.com/docs/dots/tasks-and-memory)

截至本次官方页面核对，没有建立普通用户可直接调用的通用 dot 文件上传 SDK 的接口依据。上传实现要跟随当前运行环境提供的能力。

## 接入次序

1. 用户已有可用 dot，并决定允许它使用的来源范围。
2. 用户按平台引导连接电脑；或选择只提供脱敏导出包。连接是用户配置动作，Harness 记录实际连接与文件可用情况。
3. 本地生成初始化说明，填入真实工作区和可读入口。dot 按 AGENTS、薄地图和相关理解页读取，并说明实际读到了哪些文件。
4. 选取一个用户当前真实问题，调用相关 Wiki。用户反馈直接更新对应主落点，保留表达日期和出处。
5. 初始化期间默认配置同步续读与独立理解校准，由当前 Agent 保存真实平台任务；既有关闭选择保留。读取实际任务引用与执行位置，不将待配置说成已经运行。

配置过程见 [dot 配置引导](../prompts/setup-guide.md)，开始使用个人库的提示词见 [dot 初始化](../prompts/dot-onboarding.md)。

## 两种材料交付方式

| 方式 | 适用情况 | 需要实现 |
| --- | --- | --- |
| 连接电脑读取 | 用户允许 dot 使用本机的阅读副本 | 路径说明、读取流程、本地执行与状态回写 |
| 脱敏包进入云端 | 用户希望在电脑离线时使用已提供材料 | 打包、当前可用上传工具、持久引用、云端解包和增量合并 |

当前 export 生成携带工具与工作区的包；dot 生成按提供范围筛选的日常入口和实际交接说明。在运行环境确实暴露批量上传或 Library 工具时，自动传输调用该工具并保存真实结果。工具不可用时保留本地包，用户仍可以完成交付；不要求用户提供浏览器 Cookie 或复制账号访问令牌。

原型临时上传脚本使用托管认证和内部传输端点。通用项目可以借鉴其批量状态和回执方式，不直接绑定这些内部接口，也不承诺该能力在其他用户环境可用。

## 云端读取约定

首次收到包后保存到当前环境支持的持久位置，记录真实引用和解包目录。dot 的持续笔记记住入口、相关当前认识和待处理事项；完整材料与可修订 Wiki 继续由个人库保存。

每次处理先读取当前主落点、已有确认与待核实项。新表达、明确决定和重要反馈更新对应 Wiki；重要经历与日记保留完整可用原文。将云端修改写回本地前先比较共同基线和本地变更。

## 持续任务

初始化默认配置两项任务：按用户时区每天 21:00 同步续读、每周日 10:00 校准；这是可修改的产品初始安排，旧库已有选择保留。schedule 返回两项可保存的正文和原生工具操作说明。Codex 使用当前聊天 heartbeat，dot 使用实际日程工具；校准优先放到 dot 云端，只有本地工具时登记实际位置。

maintain 的 instructions 将主动取得 ChatGPT 会话分页、Codex 增量收取、取回云端修改、长聊天分段理解和更新交付接在同一轮。获取游标和阅读位置分别保存；新消息不会抹掉尚未取完的历史。另一端的实际工作区引用随交付结果保留，返回包放入 exchange/incoming 自动合并，实际消化后 maintain --finish 交付。工具不可用时报告具体缺口，其他已获准材料继续处理。

理解校准在用户选择的时段进行，优先处理显著影响建议的矛盾、变化和未知；材料能自行澄清的先查材料。没有新增理解或需要用户操作的变化时保持安静，复用已有回答以免重复提问。

通用项目不继承原型个人库的任务 ID、电脑身份、Library ID 或历史安排。平台任务由初始化 Agent 保存，Python 只提供工作流和持久进度；本地运行需要电脑在线，云端只能处理实际取得且获准的副本。[官方任务与记忆说明](https://learn.chatgpt.com/docs/dots/tasks-and-memory)

## 当前可执行入口

详见[命令与协议](commands.md)。Bootstrap 和 onboard 都返回自动维护配置，当前 Agent 在首次引导中执行；认识展示、本人确认和真实问题处理继续沿原有阶段。dot 首次生成日常入口后，反馈、消化和同步写入自动刷新它。schedule 的两项任务在平台实际保存后分别用 --task、--confirm-ref 和 --executor 登记。

用户要求撤回资料时，withdraw 处理本地阅读副本、派生页和受管理导出；dot 再依据返回的真实引用完成远端撤回，提交实际回执。相关原生工具不可用时保留待处理状态，不把本地完成说成远端已删除。
