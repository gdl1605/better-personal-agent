# dot 接入与持续维护

更新时间：2026-10-12。主职责：首个日常入口怎样读取个人库、接收脱敏材料并回写理解。

首版把 dot 作为配置引导、日常交流和理解维护入口。dot 沿 Harness 的步骤协助用户完成来源选择与操作；本地工具组织资料、工作区和读取约定，再依据用户选择把个人 Wiki 与脱敏来源提供给 dot。

## 已核对的平台能力

dot 有云端电脑，也可以连接用户电脑并创建或继续本地工作任务。使用本地电脑时，电脑需要在线且 ChatGPT App 保持打开；电脑权限、消息入口与插件连接分别配置。[官方电脑与应用说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)

dot 使用当前对话、相关记忆和自己的持续笔记；新任务接收该任务的上下文，连接电脑不自动带来全部历史聊天。固定时间的重复工作需要保存 schedule，并设置工作、时间及时区、通知条件和结果位置。[官方任务与记忆说明](https://learn.chatgpt.com/docs/dots/tasks-and-memory)

截至本次官方页面核对，没有建立普通用户可直接调用的通用 dot 文件上传 SDK 的接口依据。上传实现要跟随当前运行环境提供的能力。

## 接入次序

1. 用户已有可用 dot，并决定允许它使用的来源范围。
2. 用户按平台引导连接电脑；或选择只提供脱敏导出包。连接是用户配置动作，Harness 记录实际连接与文件可用情况。
3. 本地生成初始化说明，填入真实工作区和可读入口。dot 按 AGENTS、薄地图和相关理解页读取，并说明实际读到了哪些文件。
4. 选取一个用户当前真实问题，调用相关 Wiki。用户反馈直接更新对应主落点，保留表达日期和出处。
5. 用户需要持续工作时，再保存采集、消化、同步与校准的任务；读取已保存的安排和实际执行结果。

配置过程见 [dot 配置引导](../prompts/setup-guide.md)，开始使用个人库的提示词见 [dot 初始化](../prompts/dot-onboarding.md)。

## 两种材料交付方式

| 方式 | 适用情况 | 需要实现 |
| --- | --- | --- |
| 连接电脑读取 | 用户允许 dot 使用本机的阅读副本 | 路径说明、读取流程、本地执行与状态回写 |
| 脱敏包进入云端 | 用户希望在电脑离线时使用已提供材料 | 打包、当前可用上传工具、持久引用、云端解包和增量合并 |

当前 export 生成携带工具与工作区的包；dot 生成按提供范围筛选的日常入口和实际交接说明。在运行环境确实暴露批量上传或 Library 工具时，自动传输调用该工具并保存真实结果。工具不可用时保留本地包，用户仍可以完成交付；不要求用户提供浏览器 Cookie 或复制账号访问令牌。

原型临时上传脚本使用托管认证和内部传输端点。通用项目可以借鉴其批量状态和回执方式，不直接绑定这些内部接口，也不承诺该能力在其他用户环境可用。

## 云端读取约定

首次收到包后保存到当前环境支持的持久位置，记录真实引用和解包目录。dot 的持续笔记记住入口、相关当前认识和待处理事项；完整材料与可修订 Wiki 继续由个人库保存。

每次处理先读取当前主落点、已有确认与待核实项。新表达、明确决定和重要反馈更新对应 Wiki；重要经历与日记保留完整可用原文。将云端修改写回本地前先比较共同基线和本地变更。

## 持续任务

建议把采集 → 凭据处理 → 消化 → 已授权同步按步骤衔接。固定周期负责补取材料与继续历史阅读，避免采集刚完成却必须等待下一天才同步。离线期间云端继续使用已经提供的材料，本地采集待电脑可用时继续。

理解校准在用户选择的时段进行，优先处理显著影响建议的矛盾、变化和未知；材料能自行澄清的先查材料。没有新增理解或需要用户操作的变化时保持安静，复用已有回答以免重复提问。

当前原型的每日时点是单用户既有安排，通用项目不继承固定时间、任务 ID、电脑身份或 Library ID。用户选择后再保存各自任务。

## 当前可执行入口

详见[命令与协议](commands.md)。使用 python3 personal-agent --workspace 个人库路径 dot 生成入口；语义处理使用 digest 的真实任务与回执。schedule 生成自然语言保存请求，平台实际保存后用 confirm-ref 登记。
