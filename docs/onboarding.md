# 用户配置与逐步接入流程

更新时间：2026-10-13。主职责：用户第一次怎样开始，之后怎样增加、改变或停止来源。

用户在本项目的 Codex 线程或已关联的 dot 中发送“初始化”“执行初始化”“安装”等启动指令，Agent 直接按 [Bootstrap](../BOOTSTRAP.md) 自动创建或恢复工作区，再在聊天中继续问答。初次默认 `~/PersonalContext`，以后沿用项目绑定的工作区；用户可以指定其他位置。Agent 使用非交互入口，命令由 Agent 执行。手动终端问答仍可用 setup。只询问当前缺少且会改变采集、处理或提供范围的选择，技术字段由工具维护。参见[命令与协议](commands.md)和[引导提示词](../prompts/setup-guide.md)。

## 首次配置

1. 用户发出初始化请求。已有项目入口直接启动；新 dot 第一次提供 Harness 位置，并按需完成电脑连接。Agent 先准备基础工作区，沿用已提供的答案，只询问缺少的目标和资料选择；称呼、时区与工作区可以随时修改。
2. 分别选择 Codex、ChatGPT、微信、健康、消费、日记或其他文件。初次未选择的来源保持关闭。
3. 对每个来源决定读取范围、是否参与个人理解、哪些内容允许 dot 使用。提供时间范围、会话或文件选择、略过列表；既可只归档，也可参与消化。
4. 根据已选来源显示实际步骤。已有本地记录的来源直接读取；需要账号导出的来源说明如何投放；需要登录或设备迁移的来源等待用户完成相应步骤。
5. 处理用户选择的首批材料，生成脱敏阅读副本。展示实际收到的范围和脱敏类型，不在结果中显示秘密值。
6. Agent 阅读首批资料并维护 Wiki。用户查看已有事实、目标、约束和重要待确认项，直接纠正；修正落到对应主落点。
7. dot 实际读取允许提供的日常入口，结合刚确认的目标、偏好和约束，直接处理用户当前的一件事。已有具体问题就继续回答；缺少时只询问当前最想解决的一件事。实际回答后才记录首次使用完成。
8. 告诉用户以后可以直接交流、补资料和纠正认识；dot 在当前环境的持续笔记中记住真实入口与维护职责。检查本次初始化配置的同步续读与独立校准两项真实任务，说明实际时间、时区、运行位置和未配置项；已有关闭选择保留。

自动维护在初始化期间和上述首轮处理衔接，不等首次使用结束后才询问。新库默认每天 21:00 同步续读、每周日 10:00 校准，均按用户时区；本人可以调整或关闭。Bootstrap/onboard 返回 schedule 请求，由当前 dot／Codex 用真实平台工具保存或更新，登记真实引用。数据来源和云端范围仍由本人选择。完整步骤见 [Bootstrap](../BOOTSTRAP.md#初始化时配置自动维护)。

## dot 怎样续接引导

Bootstrap 准备工作区，`onboard` 承接后续交互并返回当前步骤与 instructions。保存首批资料及使用范围后记录 configured，由工具收取已启用资料并提供阅读任务；dot 实际阅读、维护 Wiki 后展示认识，记录 reviewed。用户的明确纠正先写回对应主落点，直接作为本次确认，不要求再确认一遍；记录 confirmed 后，dot 读取当前 Wiki 处理具体问题，记录 used。

步骤保存于工作区的 state/onboarding.json；返回对话后从当前步骤继续，复用已有回答。配置、阅读完成、本人确认、实际回答分别记录。本人尚未确认时等其回复；没有配置外部 Agent 命令时，由当前 dot 自己读取任务并提交回执，不把工具返回的待阅读状态原样交给用户。命令、ID、路径和 JSON 回执均由 dot 处理。

例如，用户提出“帮我安排这周的课程和项目”，dot 整理后展示“课程优先、项目每周十小时”；用户纠正“这周只有五小时”。dot 写回五小时，直接据此给出本周安排，然后告诉用户以后可以继续用自然语言补充或修改。

没有启用的来源不阻止已选材料进入个人库。需要登录的步骤只影响对应来源；已有材料可以继续形成理解。第一轮形成实际可用的 Wiki 并被 dot 读取后，用户即可开始日常交流，后续逐个补充资料。

## 来源选择应分开表达

| 选择 | 用户决定的内容 |
| --- | --- |
| 收取什么 | 时间、会话、文件、账户和忽略范围 |
| 理解什么 | 参与个人 Wiki，或只保留可回查归档 |
| dot 使用什么 | Wiki、选定脱敏来源，或暂不提供该来源 |
| 继续获取什么 | 手动补充，或保存周期任务 |

模型阅读资料会将被读取的内容交给相应模型服务。界面据此区分“原件只保存在本地”与“阅读副本会被 Agent 使用”。只在本地保存原件不等于使用云端模型时数据从未离开本机。

## 各来源的操作说明

以下内容供 Agent 在用户选定对应来源后使用。每次只说明当前需要的一步；已有文件、可用工具、登录和授权直接沿用，不把所有来源的教程一次发给用户。工具返回和实际界面决定当前可执行的操作。

### ChatGPT 对话

先检查当前环境是否有可用的 ChatGPT 会话读取工具。能读取本人选定的对话时，直接获取并继续历史分页；需要账号导出时，再提供下面的步骤。

**从 ChatGPT 导出一次，再把文件交给 dot。**

1. 登录 [ChatGPT](https://chatgpt.com)，打开头像菜单，进入 **设置 → 数据控制 → 导出数据**，确认导出。
2. 收到导出邮件或短信后，使用其中的下载链接取得 ZIP 文件，保存到 dot 能访问的电脑目录。
3. 告诉 dot 文件位置，以及要整理的日期或会话范围。例如：“导入下载文件夹里的 ChatGPT 导出包，只整理最近三个月的对话。”
4. dot 从 ZIP 中读取对话 JSON，保留你和助手各自的发言、日期与出处，再整理到个人 Wiki。你也可以直接提供解压后的 `conversations.json`；有多个对话分片时，把这些 JSON 一并交给它。

导出入口及账号适用范围见 [OpenAI 官方导出说明](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data)。组织管理的工作区如果没有导出入口，需要按该工作区提供的方式取得资料。

文件导入后产生的新对话，可以补充新的导出包，或在工具可用时继续同步。

### Codex 对话

**授权本机 `.codex` 会话目录后，由 Agent 自动整理，无需逐个导出。**

1. 告诉 dot：“把我本机 Codex 的对话也接进来。”使用 dot 时，先完成电脑连接和访问授权；在本机 Codex 中操作时，按实际提示授予文件访问权限。
2. 选择日期与会话范围，例如“最近三个月”“只接入这几个项目的对话”。dot 会列出可选记录并保存你的选择。
3. Agent 默认从 `~/.codex/sessions` 和 `~/.codex/archived_sessions` 读取主会话日志，整理你的表达、相关背景与协作偏好。如果日志在其他位置，告诉它实际目录即可。
4. 后续维护会继续处理已选范围里的新记录，保留阅读进度；你可以随时调整范围或暂停。

授权对象是会话日志目录，不需要把整个 `.codex` 文件夹打包上传，也不需要提供其中的登录凭据或配置文件。

### 微信消费记录

**使用微信自带的账单下载功能，提供 CSV 或 XLSX 文件。**

1. 在手机微信打开 **我 → 服务 → 钱包 → 账单**。
2. 在账单页右上角找到 **常见问题 → 下载账单**；部分版本先从右上角的“…”进入。
3. 用途选择 **用于个人对账**，选择交易类型、起止时间，填写接收邮箱，并在微信内完成身份验证。需要更长时间时，按页面允许的范围分批导出。
4. 收到邮件后下载 ZIP，使用微信支付发来的解压密码，在自己的电脑上解压。
5. 把解压得到的 **CSV 或 XLSX** 文件交给 dot，或告诉它文件所在目录。例如：“把这个文件夹里的微信账单整理进去，先看今年的记录。”

dot 会识别账单字段、合并重复交易，保留金额、收支、交易状态和出处。之后收到新账单，再把新文件交给它即可。账单下载入口可参考[财付通官方说明](https://pay.wechatpay.cn/xdc/weardeviceagreementweb/html/agreement/tenpay_user_privacy)；逐步界面示意见[微信账单导出图解](https://home.xiaohuajizhang.com/docs/csv/import/wx/)，其中导出部分同样适用于本项目。

**支付宝账单也可以提供。** 在支付宝进入“我的 → 账单 → … → 开具交易流水证明”，选择“用于个人对账”，按提示选择范围、填写邮箱并完成验证；下载后用支付宝服务消息中的密码解压，把 CSV 交给 dot。详见[支付宝账单导出图解](https://home.xiaohuajizhang.com/docs/csv/import/alipay/)。

消费动机、预算和代付关系可以直接补充给 dot，例如“这几笔是替同学垫付的”。它会结合你的说明理解记录。

### 微信聊天记录

**当前自动读取流程使用 [wechat-use](https://github.com/leeguooooo/wechat-use)，已适配 Apple Silicon Mac 上的工具专用微信。** dot 负责安装、配置和读取命令，你按窗口完成激活、扫码登录与系统授权。

1. **选择聊天范围。** 告诉 dot 要接入哪些联系人、群聊和日期，例如“接入这两个项目群最近半年的文字记录”。
2. **准备读取工具。** dot 检查本机是否已有可用的 `wechat-use`；已有安装会复用，首次安装则按上游说明准备工具和独立的“微信 4.1.9（工具专用）”。
3. **完成首次设置。** 首次使用按工具的[激活说明](https://github.com/leeguooooo/wechat-use/blob/main/docs/install.md)，通过 Telegram 的 [@WechatCliBot](https://t.me/WechatCliBot) 向维护者申请激活码。在“微信工具设置”窗口填写激活码，用手机扫码登录工具专用微信，并完成窗口指出的 macOS 权限设置。已有有效登录和授权会继续使用。窗口流程见[工具设置指南](https://github.com/leeguooooo/wechat-use/blob/main/docs/setup.html)。
4. **补齐需要的历史。** 如果旧记录只在手机上，在微信设置中找到“聊天记录迁移与备份”，按当前版本的迁移指引将选定记录迁移到工具专用微信所在的电脑。dot 会核对实际能读到哪些会话和日期，接着处理已到达的记录。
5. **自动导入与续读。** dot 用工具读取所选会话，先处理微信文字中的明确凭据，再按日期和发言者整理到知识库。启用持续整理后，工具专用微信保持登录、电脑可访问时，dot 会继续收取新增记录。

如果只想导入一次，可以让 dot 用同一个工具把选定会话导出为 **Markdown**，再导入该文件；你不需要输入导出命令。已经有 TXT 或 Markdown 聊天记录时，也可以直接提供文件，尽量保留日期和发言者。

历史迁移是为了让旧聊天出现在工具可读取的微信会话里；微信的备份包本身不是本项目直接读取的对话格式。当前内置流程以文字为主，图片、语音和视频内容需要另行转成可读材料。

微信只读接入时，Agent 使用安装器的 `WECHAT_USE_NO_TEST_MESSAGE=1` 选项和 `wechat-use setup --skip-verify` 完成设置，跳过发送测试消息；随后使用会话列表、历史读取或 Markdown 导出接入资料。

### 自述、目标和日记

直接告诉 dot 你的背景、最近在做的事、重要约束和希望它怎样配合你。例如：

> 我现在同时上课和做一个个人项目，每周能给项目留五小时。先帮我整理这两个方向，再安排这一周。

已有日记、笔记或自我介绍时，提供 **Markdown、TXT、JSON 或 CSV** 文件，或指定包含这些文件的目录。dot 会按来源和日期接入；缺少必要背景时，再针对具体内容问你。

### 健康与生活记录

可以先口述最近的睡眠、运动、饮食和作息，也可以提供带日期的 **CSV、JSON 或文字记录**。表格尽量保留日期、项目、数值和单位，直接使用原导出字段即可。

如果资料来自健康 App 或设备，告诉 dot 应用名称和你能取得的导出文件。当前内置接入以文字和结构化记录为主，设备专有格式由 Agent 先检查实际样本，再适配解析。没有设备数据也可以从日常表达开始。

## 改变选择

用户可以追加来源、扩大或收窄时间范围、修改略过会话、改变哪些资料允许 dot 使用。配置变化决定后续采集、阅读队列和导出范围。

停止采集、停止 Agent 使用和删除已保存资料是不同操作。用户说“先别继续收取”时保留已有资料；说“以后不要用这些资料理解我”时，dot 执行撤回，移除阅读副本及其派生认识，停止收取和使用；是否删除本工作区原件按本人选择执行。

收窄日期、会话或文件范围后，旧范围对应的阅读材料和派生页撤回，再按新范围收取。当前出处记录到整页：混合来源的受影响页依据剩余获准资料重建，其他页面继续使用。旧回执和旧返回包不能恢复已撤回的内容。dot 接着执行重建任务，不让用户手工改 Wiki。

本地受管理的旧导出包会移除；已经登记的远端引用形成待执行清单，由 dot 使用原生工具删除旧包、处理解包副本和相关笔记，提交真实结果。远端未执行时保持待处理；用户自行复制但未登记的位置无法由本地工具发现，应按本人提供的实际位置处理。

## 当前命令

```text
personal-agent bootstrap  无终端输入地创建或恢复，并让当前 Agent 继续聊天引导
personal-agent init       保存称呼 时区与目标
personal-agent onboard    dot 续接认识展示、本人确认和首次使用
personal-agent sources    启用或修改来源范围
personal-agent collect    收取已启用来源
personal-agent digest     提供阅读队列并衔接当前 Agent
personal-agent export     生成允许提供给 dot 的脱敏包
personal-agent dot        生成或执行当前环境支持的 dot 接入步骤
personal-agent sync       处理本地与云端已授权更新
personal-agent status     查看接入 阅读 交付与待操作项
personal-agent withdraw   按本人请求撤回来源及派生认识
```

当前命令已实现。sources --discover 提供标题和 ID，dot 可让用户按标题选择后保存范围；status 显示接入、阅读、交付与下一步。语义处理和平台日程保存分别以实际执行回执判断。
