# 按问题读取与概述回写

主职责：判断本轮需要哪些个人背景，并维护可直接使用的简要认识。

## 先判断问题需要什么

当前 Agent 在理解用户请求时同时判断回答深度和个人背景的相关性，无需另发一次分类模型调用，也不按关键词固定分类。

| 当前问题 | 从哪里读 | 何时继续展开 |
| --- | --- | --- |
| 通用事实、知识解释、简单操作 | 当前对话和问题所属资料 | 个人背景会改变答案时才读个人概述；现有协作要求继续适用 |
| 希望快速得到个人建议 | 基本信息简要，加当前问题相关的主题概述 | 缺少会改变结论的条件时，只补对应详情；回答仍可简短 |
| 个性化规划、取舍或深入理解 | 基本信息简要 → 相关主题概述 → 会影响判断的详情 | 需要说明变化原因、核实适用日期或解决矛盾时回查对应来源 |
| 找回原话、时间、具体经历，或处理冲突 | 对应详情和来源指针 | 按问题核对原始记录，不把摘要当作逐字证据 |

用户明确说出的期望优先；未说明时，根据本轮问题是否依赖个人目标、习惯、关系或现实约束判断。简短回答仍使用会改变结论的已知背景，深入回答也只读取相关主题。已有信息足以回答时停止展开；只有重要缺口会改变答案且现有资料无法澄清时才询问本人。

## 概述分别承担什么

- [基本信息简要](../关于用户/基本信息简要.md)：少量核心背景、持续主线、当前重要约束和对回答有直接影响的协作要求，链接主题概述和事实主落点。
- 主题概述：如[人物关系概述](../生活与健康/人物关系概述.md)、[行为习惯概述](../生活与健康/行为习惯概述.md)，保存该主题的当前结论及详情入口。
- 详情页的“当前概述”：概括该人物或主题现在应怎样理解；后文保存会影响理解的具体经历、变化及依据。材料多时按人物或独立问题拆分详情。
- 原始材料：保存完整表达、时间与出处，供核对和重新理解。

概述是详情的压缩入口，事实及其依据仍有一个主落点。概述保留适用日期、必要的未知和详情链接；只有事实主落点支持的内容才进入概述。来源限制同样适用于概述，提交时保留其实际依赖的 source_keys。

## 新信息怎样回写

1. 先读受到影响的详情与现有概述，区分本人确认、记录和分析；比较表达日期、对象、范围与主张。
2. 更新事实主落点和该页当前概述。新证据改变已有结论时直接修订结论；补充经历放入相关详情，不逐批堆进当前概述。
3. 判断主题的当前认识是否变化。变化时同步改对应主题概述；只是增加佐证时保留原概述。
4. 判断变化是否影响跨主题的日常建议。核心身份、持续方向、重要约束或协作要求变化时，同步改基本信息简要；人物的普通小事和单次生活记录留在对应主题。
5. 同一轮用 digest record 提交实际有变化的页面与各自来源。feedback 先保存本人的原话与指定条目，随后由当前 Agent 完成受影响概述的语义更新；工具保存条目不等于已经提炼概述。

若一轮中断后继续，先对照当前详情与概述处理尚未反映的变化。本人本轮明确纠正优先于旧概述。校准时关注当前概述是否遗漏新结论、是否仍引用过时状态，以及是否混入大量经历。

不规定摘要必须达到某个字数，不增加固定全库扫描或完成门禁；概述只保留能帮助回答的当前认识，详情仍可按需展开。没有语义变化时不重写无关页面。
