# your-life-as-context

**让你生活中的一切，都能成为 Agent 的上下文。让你拥有一个全天候、懂你方方面面的专属 AI 专家。**

你的经历、目标、偏好、关系、日常习惯和现实约束，都可以成为它理解你的背景。通过你选择提供的聊天、笔记、消费和健康记录，Agent 把过去的经历、现在的处境和未来的打算联系起来，逐渐理解你正在做什么、为什么在意这件事，以及哪些建议适合你。

这份理解会随着新的交流和生活变化持续更新。从学习、工作到日常生活、人际关系和重要选择，你都可以和它一起想清楚、作决定、推进事情。当你补充进展、改变目标，或遇到新的现实约束，后续讨论也会接着这些变化继续。

当前以 OpenAI 的 dot 作为日常入口。你讨论一个新机会、安排下一周，或给朋友挑一份礼物时，它会结合你的经历、偏好和当前情况给出建议，让长期积累的理解用在眼前的事情上。

## 它能怎样帮你

- **学习和工作安排。** 结合你手头的任务、真正看重的目标和能投入的时间，讨论先做什么、怎样推进，以及哪些事情可以缓一缓。
- **重要选择。** 面对新的项目、合作或学习方向，一起考虑它与你长期目标的关系、你已有的经验，以及当前需要付出的代价。
- **日常生活。** 结合你提供的作息、运动、饮食和消费记录，帮助你回顾近期状态，讨论更适合自己的生活安排。
- **你在意的人和事。** 送礼、出行或准备一次沟通时，回看你们聊过的喜好和经历，让建议更贴合具体的人与关系。

同一件事可以持续聊下去。你补充进展、改变主意，或发现上次的安排不合适，它会把这些变化接进来，和你继续调整。

## 目前支持哪些上下文来源

- **ChatGPT 对话。** 你过去讨论过的问题、反复思考的想法、做过的选择，以及希望 AI 怎样解释和回应。已经讲过的背景，可以成为之后继续讨论的起点。
- **Codex 对话。** 你在项目、工作和学习中与 AI 的交流，包括目标、推进过程和协作偏好，帮助它理解你当前把精力放在哪里。
- **微信聊天（暂只支持 Mac）。** 你选择的联系人和群聊文字记录，让它了解你愿意分享的人际背景与近期事情，并区分你的表达和其他人的观点。
- **消费记录。** 微信支付、支付宝账单，以及你对这些支出的说明。例如，哪些是日常开销，哪些是替朋友垫付，哪些与某个阶段的计划有关。
- **自述、日记与笔记。** 你的背景、经历、目标、感受和长期想法。没有历史资料也可以开始，直接聊聊最近在做什么、有什么困扰、希望它怎样配合你。
- **健康与生活记录。** 你提供的睡眠、运动、饮食、作息等记录，以及你对近期状态的感受，让它在讨论生活安排时考虑这些实际情况。

这些来源都可选，可以只接入一种，也可以逐步增加。你选好之后，AI 会在实际使用时带你完成接入；需要导出、登录或授权时，再给出对应指引。

## 从一次初始化开始

先获取源码：

```bash
git clone https://github.com/gdl1605/your-life-as-context.git
cd your-life-as-context
```

本地开发与 CI 使用 Python 3.12，运行代码只依赖标准库。dot、文件交付和自动调度使用当前环境提供的实际能力；具体边界见[当前实现](docs/roadmap.md)。

在 Codex 中打开本项目，或让 dot 关联本项目，然后说：

> 执行初始化

接下来，它会在对话里带你完成这几件事：

1. **先了解你想解决什么。** 可以从一个具体问题开始，也可以先介绍自己的背景、目标和重要约束。已经说过的信息会继续沿用。
2. **选择愿意提供的资料。** 你决定接入哪些来源、哪些日期或会话，以及允许它使用的范围。暂时只用自述也可以。
3. **看看它怎样理解你。** 阅读首批资料后，它会简短说明对你的目标、处境和偏好的理解，你可以直接补充或纠正。
4. **一起处理一个实际问题。** 比如安排这一周、梳理一个选择，或讨论眼前的难题，让刚刚了解的信息直接用起来。
5. **把后续维护一起配置好。** 默认安排每日同步与整理、每周回顾理解；它会说明实际保存的安排，你可以调整时间、暂停某项，或改成按需进行。

不必等所有历史聊天都读完才开始使用。已有的理解先用起来，其余资料按进度继续；中途离开，回来也能接着进行。

## 真实例子：朋友快过生日了

下面根据真实使用对话精简，已去除人名，生日以 xx 代替。

> **你：** 朋友快过生日了，我送什么比较好？
>
> **AI：** 我先看看她之前跟你聊过的喜好。翻到她说生日是 **xx 月 xx 日**了。还有一个可以排除的选项：她去年说收到过六个一次性胶片相机，所以这次先避开，免得又撞礼物。
>
> **AI：** 我现在更推荐一小套胶卷，配个好看的收纳盒。她之前跟你说相机是 **佳能 EOS 55**，还分享过刚洗出来的胶片照片，也约过你一起拍。你去年其实就想送胶卷，只是当时还不知道她的相机型号；现在这个信息已经有了，今年刚好可以接上。
>
> **AI：** 可以考虑 **柯达 Gold 200 和 UltraMax 400**，共 3–4 卷 135 胶卷，再附张简短的生日卡，留给她平时拍照、出去玩用。
>
> **AI：** 如果你更想送一件能长期用的东西，轻便的相机肩带也是一个选择。她最近提过旅行不想背太重，所以我不太倾向大摄影包。你这次大概想花多少钱？

## 随着你的生活继续了解你

新的聊天、经历和决定，会不断补充它对你的认识。读过的历史可以继续回看，尚未读完的资料会接着理解；当你说“这个项目已经结束了”或“最近只能投入五小时”，后续讨论也应跟着你的当前情况调整。

重要的疑问会向你确认，你的纠正会更新原来的认识。日常维护默认只在有重要变化、遇到实际问题或需要你操作时通知，时间和频率都可以自己决定。

日常云端交流可以继续使用已经提供的信息；需要从你的电脑获取新资料时，电脑须保持可连接。

## 隐私与安全

**你决定它能读取什么，以及哪些内容可以留在云端。** 每个来源分别选择，可以限定会话、日期或文件；未选来源不采集。对你的理解也可以随时查看、补充和纠正。

默认方案使用你的电脑和你授权的 OpenAI 服务，本项目不另设收集个人资料的后台，也不要求把账号凭据交给项目作者。提供给 AI 阅读的内容会由 OpenAI 模型处理；本地保存原件与允许模型阅读，是两件分别由你决定的事。

- **原件与阅读材料分开。** 原件保留在本地，日常使用和云端交付从获准的阅读材料与已整理的认识中取内容。你可以只让云端保留整理后的认识，也可以提供选定的原文副本。
- **已识别的凭据先处理。** 当前默认对微信记录中的明确密码、密钥、访问令牌等进行本地识别，在 AI 阅读前替换阅读副本中的秘密值，原件不改写。Codex、ChatGPT 等来源目前未默认接入这项筛除；它也不等于对所有个人信息自动匿名化。
- **暂停与撤回分别处理。** 暂停只停止继续收取；明确撤回时，处理相关阅读材料和据此形成的认识，并通过实际文件工具撤回已登记的云端副本。是否删除本地原件由你决定。

电脑访问和账号权限由操作系统及 OpenAI 平台管理。项目的范围选择和凭据筛除负责控制提供的材料，不替代平台权限，也不承诺识别任意格式里的所有秘密值。具体范围见[资料与隐私说明](docs/privacy-and-sync.md)。

## 这套 Harness 怎样管理上下文

聊天历史会持续增长，一次模型调用能容纳的上下文有限；你的目标和处境也会变化，过去的结论需要修订。这套 Harness 将个人化所需的信息保存在可持续更新的外部上下文中，再让 Agent 根据当前问题读取和维护。

Agent 负责实际阅读、判断信息的含义、形成理解和回答问题；Harness 负责组织获准资料、保存出处与进度、写入理解页面，并把后续采集、校准和同步衔接起来。

### 来源、Wiki 和阅读进度各有职责

- **来源保存依据。** 聊天、日记和账单保留各自的日期、发言者与出处。Agent 可以回查一条认识来自哪段表达，也需要区分你说的话、他人的观点和历史助手的建议。
- **Wiki 保存当前理解。** 背景、目标、约束、协作偏好和重要经历按主题组织成相互关联的 Markdown 页面。你可以直接查看和修改，Agent 也可以随着材料增加补充新的主题。
- **阅读进度记录已经处理到哪里。** 每份材料保存当时的版本、实际阅读结果和未读完的位置。选择用于理解的材料在导入后进入待处理队列；实际读过并提交结果后，才更新阅读状态。

原始记录让结论可以回查，Wiki 让当前认识可以反复使用，阅读进度让长期整理可以中断后继续。三者通过来源引用联系起来。

### 新资料增量接入，长聊天分段续读

每轮维护检查所选来源的新增和变化，把未读材料、有更新的材料以及上次读到一半的材料列入队列。长聊天从完整文字中拆出阅读段，记录读到哪条消息、哪段文字；相同版本从上次位置继续，来源更新后重新检查变化。

获取进度与理解进度分别保存。例如，ChatGPT 还有历史页面没取完，同时已经取得的聊天也可能只读了一部分，这两项工作都有各自的续接位置。你可以先使用已经形成的认识，其余历史继续处理。阅读记录对应当时的材料版本，后来出现的新消息仍会进入待处理队列。

### Wiki 由 Agent 维护，认识随新证据修订

阅读每一批材料时，Agent 先对照已有 Wiki，再判断哪些内容补充了背景、改变了目标、表达了约束，或提出了新的协作要求。一般知识问答可以只分类；涉及你的个人信息才整理到对应主题，并保留依据、适用日期和仍待确认的部分。

维护时优先更新已有页面，为同一事实保留一个主要记录位置，其他页面通过链接引用。例如，你说“这周项目只有五小时”，Agent 应把本周的时间约束更新为五小时，并保留“这周”的适用范围，供后续安排使用。

理解过程中还要区分长期方向、阶段活动与偶发兴趣，结合实际表达判断其重要性。本人明确事实与 Agent 的分析分别表述；你提出纠正时，原话和日期作为新依据写回对应位置，已建立的日常入口随之刷新。

### 回答时，沿导航找到相关上下文

日常使用从一份简短导航开始，沿当前问题进入相关主题页。来源索引和主题索引帮助 Agent 找到支撑这些认识的材料；需要确认原话、时间或处理矛盾时，再打开对应聊天或记录。

这种组织方式缩小了每次需要阅读的范围，同时保留细节回查的路径。讨论本周安排时，可以结合目标和可用时间；讨论生日礼物时，可以回到相关聊天，核对相机型号、以往礼物和最近提到的偏好。

### 把日常更新与理解校准安排成持续工作

初始化时，当前 Agent 使用 dot／Codex 的实际调度能力配置两项工作：日常同步与续读，以及独立的理解校准。Harness 保存对应的职责、安排和真实任务引用，已有任务沿用原引用更新。

一轮日常维护先取回另一端已有的修改，再收取所选来源的新记录；随后继续阅读、更新 Wiki，并把允许提供的内容同步到日常入口与云端。收取、阅读、页面更新和交付分别记录结果，中断后依据各自进度续接。

理解校准关注那些会影响后续建议的变化：某个目标是否已经结束，旧判断是否仍适用，新表达与已有认识是否冲突。Agent 先查已有材料，只有重要疑问仍无法澄清时才向你确认。这样，定期维护既继续吸收信息，也回看已有认识是否需要调整。

### 本地与云端维护同一份可修订的理解

同步时按你的选择提供 Wiki，或连同选定来源副本一起提供。页面所依据的来源也参与范围判断，依赖未获准资料的认识不会被默认加入交付内容。

两端合并时，以此前共同的内容为基线：只有一端变化，就应用该变化；两端都改过，则保留双方修改，交给 Agent 根据出处、日期和你的决定合并。云端形成的新表达与纠正也可以返回本地，继续影响后续使用。

范围收窄或资料撤回后，相关认识按仍获准的来源重新整理。旧阅读任务和旧返回包会检查当前使用范围，避免重新带入已撤回的信息。语义理解由 Agent 完成，定时触发与文件传输由实际运行环境执行，Harness 将这些步骤和持久状态连接起来。
