# Personal Agent Harness

**由 dot 带你建立、使用和持续维护自己的个人知识库。**

你选择愿意提供的资料，dot 从中整理你的背景、目标、约束、经历和协作偏好，保存为可查看、可修改、有出处的个人 Wiki。之后讨论问题、安排事情或作出选择时，dot 读取相关认识；你有新的表达、决定或纠正，它就更新这份库。

用户通过自然语言完成这些事。创建工作区、接入资料、整理文件、保存阅读进度、更新认识和同步副本，都由 Agent 操作。

当前版本：0.1。更新时间：2026-10-13。本地工具使用 Python 3.9 及以上和标准库，无需额外安装 Python 依赖。

## 这个项目具体提供什么

Harness 是支撑个人 Agent 工作的一套工具、规则和流程。它把分散的资料变成可以持续使用的个人上下文，首个日常入口是 OpenAI 的 dot。

- **一份个人 Wiki。** 保存你的背景、目标、约束、经历和协作偏好，每条重要认识都能回查出处，也能由你纠正。
- **一套持续整理流程。** 接入新资料、接着读未读完的历史、更新认识，让知识库随你的实际情况变化。
- **一个 dot 日常入口。** 回答问题时读取相关认识，交流后写回变化；选择云端副本后，电脑离线时也可以使用已提供的内容。

这里的“个人知识库”首先围绕你本人建立：你在做什么、看重什么、受哪些条件约束、经历过什么、希望 Agent 怎样配合你。项目资料、知识问答和他人的观点保留自己的归属，个人结论依据你的表达和实际记录形成。

资料保存为 Markdown、JSON 等本地文件。Wiki 是你可以直接查看、修改、备份和迁移的持久资料层；dot 是日常交流与执行入口。

## 怎样开始

在这个项目的 Codex 对话，或已经关联项目的 dot 中，直接说：

> 初始化

“执行初始化”“开始安装”“帮我配置个人 Agent”也会进入同一流程。已有工作区时会继续使用原来的资料与选择。

如果是第一次让一个新的 dot 使用项目，先把项目文件夹放到电脑上并告诉它位置，例如：

> 用 `/项目路径/personal agent` 带我建立个人知识库。我想让你先帮我安排学习和个人项目。

使用本机文件时，在 dot 的电脑设置里完成一次电脑访问授权。此后 dot 可以通过已连接电脑操作项目；使用本机期间保持电脑在线、ChatGPT App 打开。dot 自己的云端电脑可以在你的设备离线时继续工作。[OpenAI 官方电脑连接说明](https://learn.chatgpt.com/docs/dots/computers-and-apps)

个人库初次默认放在 `~/PersonalContext`，也可以在对话中指定其他位置。项目会记住已选工作区，下次继续使用。**只提供一段自述或一个当前目标就可以起步，其他资料以后逐渐增加。**

## 你可以选择提供哪些上下文

以下来源都可选，可以先接一种，以后再补充。告诉 dot 你选哪一种、愿意提供什么范围，它会带你完成对应步骤。

- [ChatGPT 对话](#chatgpt-对话)：从账号导出历史对话，交给 dot 整理。
- [Codex 对话](#codex-对话)：授权读取本机 `.codex` 会话记录，之后自动整理。
- [微信消费记录](#微信消费记录)：从微信支付下载个人对账账单。
- [微信聊天记录](#微信聊天记录)：通过 `wechat-use` 读取选定会话，或提供已经导出的文字。
- [自述、目标和日记](#自述目标和日记)：直接聊，或提供现有文件。
- [健康与生活记录](#健康与生活记录)：提供自己记录的文字、表格或设备导出资料。

### ChatGPT 对话

**从 ChatGPT 导出一次，再把文件交给 dot。**

1. 登录 [ChatGPT](https://chatgpt.com)，打开头像菜单，进入 **设置 → 数据控制 → 导出数据**，确认导出。
2. 收到导出邮件或短信后，使用其中的下载链接取得 ZIP 文件，保存到 dot 能访问的电脑目录。
3. 告诉 dot 文件位置，以及要整理的日期或会话范围。例如：“导入下载文件夹里的 ChatGPT 导出包，只整理最近三个月的对话。”
4. dot 从 ZIP 中读取对话 JSON，保留你和助手各自的发言、日期与出处，再整理到个人 Wiki。你也可以直接提供解压后的 `conversations.json`；有多个对话分片时，把这些 JSON 一并交给它。

导出入口及账号适用范围见 [OpenAI 官方导出说明](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data)。组织管理的工作区如果没有导出入口，需要按该工作区提供的方式取得资料。

如果当前环境已经提供 ChatGPT 会话读取工具，也可以让 dot 直接读取你选定的对话；它会接着读取可取得的历史。文件导入后产生的新对话，可以补充新的导出包，或在工具可用时继续同步。

### Codex 对话

**授权本机 `.codex` 会话目录后，由 Agent 自动整理，无需逐个导出。**

1. 告诉 dot：“把我本机 Codex 的对话也接进来。”使用 dot 时，先完成上面的电脑连接；在本机 Codex 中操作时，按实际提示授予文件访问权限。
2. 选择日期与会话范围，例如“最近三个月”“只接入这几个项目的对话”。dot 会列出可选记录并保存你的选择。
3. Agent 默认从 `~/.codex/sessions` 和 `~/.codex/archived_sessions` 读取主会话日志，整理你的表达、相关背景与协作偏好。如果日志在其他位置，告诉它实际目录即可。
4. 后续维护会继续处理已选范围里的新记录，保留阅读进度；你可以随时调整范围或暂停。

授权对象是会话日志目录，不需要把整个 `.codex` 文件夹打包上传，也不需要提供其中的登录凭据或配置文件。

### 微信消费记录

**使用微信自带的账单下载功能，提供 CSV 或 XLSX 文件。**

1. 在手机微信打开 **我 → 服务 → 钱包 → 账单**。
2. 在账单页右上角找到 **常见问题 → 下载账单**；部分版本先从右上角的“…”进入。
3. 用途选择 **用于个人对账**，选择交易类型、起止时间，填写接收邮箱，并在微信内完成身份验证。需要更长时间时，按页面允许的范围分批导出。
4. 收到邮件后下载 ZIP，使用微信支付发来的解压密码，在自己的电脑上解压。
5. 把解压得到的 **CSV 或 XLSX** 文件交给 dot，或告诉它文件所在目录。例如：“把这个文件夹里的微信账单整理进去，先看今年的记录。”

dot 会识别账单字段、合并重复交易，保留金额、收支、交易状态和出处。之后收到新账单，再把新文件交给它即可。账单下载入口可参考[财付通官方说明](https://pay.wechatpay.cn/xdc/weardeviceagreementweb/html/agreement/tenpay_user_privacy)；逐步界面示意见[微信账单导出图解](https://home.xiaohuajizhang.com/docs/csv/import/wx/)，其中导出部分同样适用于本项目。

**支付宝账单也可以提供。** 在支付宝进入“我的 → 账单 → … → 开具交易流水证明”，选择“用于个人对账”，按提示选择范围、填写邮箱并完成验证；下载后用支付宝服务消息中的密码解压，把 CSV 交给 dot。详见[支付宝账单导出图解](https://home.xiaohuajizhang.com/docs/csv/import/alipay/)。

消费动机、预算和代付关系可以直接补充给 dot，例如“这几笔是替同学垫付的”。它会结合你的说明理解记录。

### 微信聊天记录

**当前自动读取流程使用 [wechat-use](https://github.com/leeguooooo/wechat-use)，已适配 Apple Silicon Mac 上的工具专用微信。** dot 负责安装、配置和读取命令，你按窗口完成激活、扫码登录与系统授权。

1. **选择聊天范围。** 告诉 dot 要接入哪些联系人、群聊和日期，例如“接入这两个项目群最近半年的文字记录”。
2. **准备读取工具。** dot 检查本机是否已有可用的 `wechat-use`；已有安装会复用，首次安装则按上游说明准备工具和独立的“微信 4.1.9（工具专用）”。
3. **完成首次设置。** 首次使用按工具的[激活说明](https://github.com/leeguooooo/wechat-use/blob/main/docs/install.md)，通过 Telegram 的 [@WechatCliBot](https://t.me/WechatCliBot) 向维护者申请激活码。在“微信工具设置”窗口填写激活码，用手机扫码登录工具专用微信，并完成窗口指出的 macOS 权限设置。已有有效登录和授权会继续使用。窗口流程见[工具设置指南](https://github.com/leeguooooo/wechat-use/blob/main/docs/setup.html)。
4. **补齐需要的历史。** 如果旧记录只在手机上，在微信设置中找到“聊天记录迁移与备份”，按当前版本的迁移指引将选定记录迁移到工具专用微信所在的电脑。dot 会核对实际能读到哪些会话和日期，接着处理已到达的记录。
5. **自动导入与续读。** dot 用工具读取所选会话，先处理微信文字中的明确凭据，再按日期和发言者整理到知识库。启用持续整理后，工具专用微信保持登录、电脑可访问时，dot 会继续收取新增记录。

如果只想导入一次，可以让 dot 用同一个工具把选定会话导出为 **Markdown**，再导入该文件；你不需要输入导出命令。已经有 TXT 或 Markdown 聊天记录时，也可以直接提供文件，尽量保留日期和发言者。

历史迁移是为了让旧聊天出现在工具可读取的微信会话里；微信的备份包本身不是本项目直接读取的对话格式。当前内置流程以文字为主，图片、语音和视频内容需要另行转成可读材料。

### 自述、目标和日记

直接告诉 dot 你的背景、最近在做的事、重要约束和希望它怎样配合你。例如：

> 我现在同时上课和做一个个人项目，每周能给项目留五小时。先帮我整理这两个方向，再安排这一周。

已有日记、笔记或自我介绍时，提供 **Markdown、TXT、JSON 或 CSV** 文件，或指定包含这些文件的目录。dot 会按来源和日期接入；缺少必要背景时，再针对具体内容问你。

### 健康与生活记录

可以先口述最近的睡眠、运动、饮食和作息，也可以提供带日期的 **CSV、JSON 或文字记录**。表格尽量保留日期、项目、数值和单位，直接使用原导出字段即可。

如果资料来自健康 App 或设备，告诉 dot 应用名称和你能取得的导出文件。当前内置接入以文字和结构化记录为主，设备专有格式由 Agent 先检查实际样本，再适配解析。没有设备数据也可以从日常表达开始。

## 导入后，dot 会带你实际用起来

1. **整理首批资料。** dot 保存所选来源和范围，阅读材料、建立 Wiki；历史资料较多时会保存进度，之后续读。
2. **请你核对认识。** 它简短说明已经理解的背景、目标、约束和重要待确认项，你直接确认或纠正。
3. **用更新后的认识解决当前问题。** 例如它认为你每周有十小时做项目，你纠正“这周只有五小时”，它就更新约束，再给出适合五小时的安排。
4. **确定后续维护。** 初始化默认配置按你所在时区每天 21:00 同步与续读、每周日 10:00 校准理解；你可以改时间、关闭某项，或全部改成按需整理。dot 会使用实际平台工具保存任务，并说明结果。

资料用途也可以直接说：只在本地归档、让 Agent 阅读并形成认识、让日常 dot 只使用 Wiki，或同时使用选定原文副本。阅读阶段使用 OpenAI 模型；需要电脑离线时也能使用，就选择在 OpenAI dot 云端保留相应副本。

中途离开后可以续接，明确纠正本身可以作为确认。**你不用记命令、编辑配置文件或整理会话 ID。** 详见[完整引导流程](docs/onboarding.md)。

## 日常怎么用

例如，你可以这样和 dot 聊：

> **你：** 帮我安排这周，项目只能投入五小时。
>
> **dot：** 好，我会按五小时安排项目，结合你的课程和截止时间排出这一周。

> **你：** 这个项目已经结束了。
>
> **dot：** 我会更新记录，之后安排时间时不再把它算进去。

> **你：** 整理改到晚上九点半，没变化就不用通知。
>
> **dot：** 好，我来调整任务，保存后告诉你结果。

## 数据放在哪里，怎样保护

### 本地知识库 + 你自己的 OpenAI 服务

**标准使用路径中的个人资料由你的电脑和你授权的 OpenAI 服务处理。项目本身不设置收集个人资料的后台，也不把知识库传给项目作者。** 原应用里的历史资料继续由原应用保存；本项目生成的个人库和获准云端副本分别放在你的本地工作区与 OpenAI dot 环境中。

- **本地工作区**保存原件、阅读副本、来源索引和 Wiki，供你查看、修订和备份。
- **OpenAI 模型服务**处理 Agent 实际阅读的内容，用于理解资料、更新认识和回答问题。
- **你自己的 OpenAI dot 云端环境**保存你选择提供的副本与持续笔记，支持电脑离线后的交流与工作。

使用 OpenAI 模型理解资料，本就需要把被读取的内容交给 OpenAI 处理。**采用 dot 云端，是在同一个 OpenAI 服务体系里延续这项服务，没有再增加一个由本项目运营的数据保管方。** 云端保存的是供持续使用的副本，范围由你选择；你也可以选择让日常 dot 只保留整理出的认识。dot 的云端电脑可以保留工作状态、文件和会话。[OpenAI 官方云端电脑说明](https://learn.chatgpt.com/docs/dots/computers-and-apps#use-the-cloud-computer)

本地文件由你的电脑账户、文件权限和磁盘保护管理；OpenAI 侧的数据使用通过你自己的 ChatGPT 数据控制设置管理。[OpenAI 官方数据设置说明](https://learn.chatgpt.com/docs/dots/controls#manage-data-settings)

### 项目具体做了哪些保护

- **按你的选择收取与提供。** 外部来源分别启用，日期、会话、文件和日常提供范围分别保存；未选来源不采集。
- **原件与阅读副本分开。** 原件保留在本地，日常入口和导出包从获准的阅读副本与 Wiki 生成，不直接打包原件目录。
- **先处理凭据，再交给模型。** 当前基础筛除覆盖微信中的明确密码、密钥、访问令牌等内容，保留理解所需语义。Codex、ChatGPT 等其他来源当前按选定内容接入；姓名、关系、健康和消费信息由使用范围管理。
- **登录沿用你自己的账号。** 登录、扫码和授权通过平台提供的界面完成；常规使用不需要向项目作者提交密码、Cookie 或 OpenAI API key。
- **认识可以纠正，资料可以撤回。** 收窄范围或停止使用时，撤下对应阅读副本与派生认识；旧回执和旧返回包不会把它们恢复回来。已登记的云端副本由 dot 使用实际文件工具处理，并保存结果。

本项目管理提供给 Agent 的文件与使用范围，电脑和账号权限由 OpenAI 平台及操作系统管理。删除云端内容时，dot 按其实际保存位置处理文件、副本和相关笔记；对话、Library 文件与记忆分别管理。[OpenAI 官方保存与删除说明](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-cloud-security#data-handling-and-retention)

上述数据路径针对使用 OpenAI dot 的标准方案。额外连接第三方应用，或自行配置其他模型、上传器和存储服务时，数据去向随你选择的服务变化。具体处理方式见[凭据筛除与上下文同步](docs/privacy-and-sync.md)。

## 本地会得到哪些文件

项目代码与个人资料分开放置。项目目录保存通用工具、规则、模板和虚构示例；每个人有自己独立的个人工作区：

```text
PersonalContext/
  config.json          你的来源选择、使用范围和时区
  inbox/               待接入的资料
  raw/                 本地保留的原件
  agent-context/
    wiki/              可以查看和修订的个人认识
    sources/           来源视图与阅读副本
    state/             阅读进度
  dot-context/         供 dot 日常读取的当前发布副本
  exports/             按提供范围生成的资料包
  state/               引导、同步和交付等运行记录
```

你可以直接查看 Wiki，或在聊天里让 dot 展示某个主题。通常由 Agent 维护来源索引和运行记录。撤回时，混合来源的受影响页面会根据仍获准的资料重建，其他页面继续使用。

## 当前能力与扩展

当前具备自然语言启动、来源选择、资料导入、微信凭据处理、增量与分段阅读、Wiki 维护、首次认识确认、实际问题使用、日常入口刷新、资料撤回、上下文打包和返回合并。

语义理解由 dot 或当前 Agent 完成；本地工具负责组织材料与保存状态。ChatGPT 历史读取、云端上传和周期任务使用当前环境实际提供的工具。遇到需要导出、登录或连接的步骤，dot 会说明本人要完成的操作，并继续处理已有材料。

本机文件导入可跨平台使用，微信实时读取首先适配 macOS 的现有读取工具。新的来源格式和其他 Agent 可沿用同一套上下文与回写流程扩展。

修改实现前先读 [AGENTS.md](AGENTS.md)。自然语言启动读取 [BOOTSTRAP.md](BOOTSTRAP.md)，后续提示词见[配置引导](prompts/setup-guide.md)、[dot 初始化](prompts/dot-onboarding.md)、[周期消化](prompts/daily-digest.md)与[理解校准](prompts/calibration.md)。

```bash
# 以下是 Agent 的操作接口；日常用户直接通过对话使用。
python3 personal-agent bootstrap
python3 personal-agent --workspace ~/PersonalContext onboard
python3 personal-agent --workspace ~/PersonalContext status

# 开发时运行现有测试。
python3 -m unittest discover -s tests -v
```

微信凭据处理可单独使用，见[使用说明](docs/wechat-redaction.md)和[脚本](scripts/redact_wechat.py)。外部 Agent 和上传器可通过已有运行协议接入，具体参数由 [commands.md](docs/commands.md) 维护。

微信只读接入时，Agent 使用安装器的 `WECHAT_USE_NO_TEST_MESSAGE=1` 选项和 `wechat-use setup --skip-verify` 完成设置，跳过发送测试消息；随后使用会话列表、历史读取或 Markdown 导出接入资料。
